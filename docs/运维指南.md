# QQ Bot 运维指南

本文仅适用于本项目的 Linux 服务器生产部署。默认部署目录为 `/opt/qqbot`，使用 `docker-compose.server.yml` 管理以下服务：

| 服务 | 作用 |
| --- | --- |
| `qq-bot` | QQ 消息处理、会话持久化与模型调用 |
| `napcat` | 登录机器人 QQ、收发 QQ 消息与提供 OneBot WebSocket |
| `postgres` | 保存用户、群组与会话历史 |
| `migration-files` | 首次启动时向 PostgreSQL 初始化卷复制 SQL，成功后退出 |

## 1. 命令前提

所有以下命令先进入项目目录：

```bash
cd /opt/qqbot
```

下文命令均以服务器部署配置为准：

```bash
sudo docker compose -f docker-compose.server.yml
```

如果本地使用的是源码版 `docker-compose.yml`，不要混用本指南中的 `docker-compose.server.yml` 命令。

## 2. 查看运行状态

```bash
sudo docker compose -f docker-compose.server.yml ps
```

显示当前服务的容器状态、镜像、端口和健康状态。正常情况下 `qq-bot`、`napcat`、`postgres` 应处于运行状态；`migration-files` 完成初始化后显示为退出码 `0` 是正常现象。

```bash
sudo docker compose -f docker-compose.server.yml ps -a
```

额外显示已停止容器，适合排查 `migration-files` 或异常退出服务。

```bash
sudo docker compose -f docker-compose.server.yml config --quiet
```

校验 Compose 文件与 `.env` 是否能正确解析，不启动、不重启任何容器。

## 3. 查看日志

```bash
sudo docker compose -f docker-compose.server.yml logs --tail=200 qq-bot
```

查看机器人最近 200 行日志，用于排查模型调用、OneBot 连接和消息处理错误。

```bash
sudo docker compose -f docker-compose.server.yml logs --tail=200 napcat
```

查看 NapCat 登录、二维码、WebUI Token 与 OneBot 服务端启动日志。

```bash
sudo docker compose -f docker-compose.server.yml logs --tail=200 postgres
```

查看 PostgreSQL 初始化、健康检查和数据库错误。

```bash
sudo docker compose -f docker-compose.server.yml logs -f qq-bot
```

持续跟踪机器人日志；按 `Ctrl+C` 仅停止日志输出，不会停止容器。将服务名替换为 `napcat` 或 `postgres` 可跟踪对应服务。

## 4. 健康检查

```bash
curl -i http://127.0.0.1:3000/health/live
curl -i http://127.0.0.1:3000/health/ready
```

`/health/live` 为 HTTP `200` 表示机器人进程存活；`/health/ready` 为 HTTP `200` 表示 PostgreSQL 与 OneBot WebSocket 已就绪。`/health/ready` 为 HTTP `503` 时请参考 [排障指南](排障指南.md)。

## 5. 重启服务

```bash
sudo docker compose -f docker-compose.server.yml restart qq-bot
```

仅重启机器人进程，适合临时恢复服务；不会重新读取 `.env`。

```bash
sudo docker compose -f docker-compose.server.yml restart napcat
```

仅重启 NapCat。通常会保留登录状态，但 QQ 平台要求重新验证时仍需重新扫码。

```bash
sudo docker compose -f docker-compose.server.yml up -d --force-recreate qq-bot
```

运行中的容器不会自动重新读取 `.env`。修改实际生效的 `.env` 后，使用上述命令重新创建机器人容器；仅执行 `restart qq-bot` 不会加载新的环境变量。`.env.server.example` 只是模板，修改它不会影响已部署服务。

该操作适用于 `ALLOWED_GROUP_IDS`、`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_SYSTEM_PROMPT`、`LLM_HISTORY_LIMIT` 等一般机器人配置。重新创建后执行以下检查：

```bash
sudo docker compose -f docker-compose.server.yml ps
sudo docker compose -f docker-compose.server.yml logs --tail=200 qq-bot
curl -i http://127.0.0.1:3000/health/ready
```

预期 `/health/ready` 返回 HTTP `200`，且 `qq-bot` 日志显示 OneBot WebSocket 已连接。

修改 `NAPCAT_TOKEN` 时，还必须在 NapCatQQ WebUI 的对应 WebSocket 服务端配置中填写完全相同的 Token，再重新创建 `qq-bot` 容器。

`POSTGRES_PASSWORD`、`POSTGRES_USER` 和 `POSTGRES_DB` 不属于一般配置。已有 PostgreSQL 数据卷不会因修改 `.env` 自动更新数据库账号、密码或数据库名；应先完成数据库侧迁移，再重新创建 `qq-bot`。不要通过删除 PostgreSQL 数据卷来应用这些修改。

```bash
sudo docker compose -f docker-compose.server.yml down
sudo docker compose -f docker-compose.server.yml up -d
```

停止并重新启动整套服务，保留所有命名卷数据。不要在日常运维中添加 `-v` 参数。

## 6. 更新机器人镜像

生产环境不在服务器构建源码。更新前先在 `.env` 将 `QQ_BOT_IMAGE` 改为目标发布版本，例如：

```dotenv
QQ_BOT_IMAGE=ghcr.io/fncheng/qqbot:v0.1.0
```

然后执行：

```bash
sudo docker compose -f docker-compose.server.yml pull qq-bot migration-files
sudo docker compose -f docker-compose.server.yml up -d qq-bot
sudo docker compose -f docker-compose.server.yml ps
sudo docker compose -f docker-compose.server.yml logs --tail=200 qq-bot
curl -i http://127.0.0.1:3000/health/ready
```

`migration-files` 与 `qq-bot` 必须使用相同镜像版本。确认 `/health/ready` 返回 HTTP `200` 后，再在 QQ 中发送 `/ping` 验证。

### 回退到上一版本

将 `.env` 中的 `QQ_BOT_IMAGE` 改回已验证的上一版本标签，再执行：

```bash
sudo docker compose -f docker-compose.server.yml pull qq-bot migration-files
sudo docker compose -f docker-compose.server.yml up -d qq-bot
```

回退镜像不会自动回退数据库结构；若发布版本包含数据库迁移，必须先确认迁移是否可逆。

## 7. 备份 PostgreSQL 数据

先创建仅供备份文件使用的目录：

```bash
mkdir -p backups
```

导出当前数据库：

```bash
sudo docker compose -f docker-compose.server.yml exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' > backups/qq_bot-$(date +%F-%H%M%S).sql
```

该命令从 PostgreSQL 容器内部读取数据库用户名和数据库名，并在服务器的 `backups/` 目录生成 SQL 备份。备份完成后应将文件复制到服务器外的安全存储。

## 8. 进入 PostgreSQL 检查数据

```bash
sudo docker compose -f docker-compose.server.yml exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

进入交互式 `psql`。常用只读命令：

```sql
\dt
\d conversations
SELECT COUNT(*) FROM conversations;
```

输入 `\q` 退出。生产数据库执行 `DELETE`、`DROP` 或手工迁移前，应先完成备份并确认目标。

## 9. 访问 NapCat WebUI

WebUI 仅绑定服务器本机 `127.0.0.1:6099`。在自己的电脑上建立 SSH 隧道：

```bash
ssh -L 6099:127.0.0.1:6099 <服务器用户名>@<服务器公网IP>
```

然后浏览器访问 `http://127.0.0.1:6099/webui`。首次 WebUI Token 通过以下命令查看：

```bash
sudo docker compose -f docker-compose.server.yml logs --tail=200 napcat
```

不要将 `6099`、OneBot `3001` 或 PostgreSQL `5432` 暴露到公网。

## 10. 禁止的高风险操作

```bash
sudo docker compose -f docker-compose.server.yml down -v
```

该命令会删除命名卷，造成 PostgreSQL 会话数据、NapCat 登录状态与配置丢失。除非明确决定清空所有持久化数据，否则不得执行。

同样不要使用 `.env.server.example` 或新的发布包模板直接覆盖生产 `.env`，否则会覆盖现有 API Key、数据库密码与 OneBot Token。
